# 订单量超申购量、最终订单数、订单数量输入

## 问题描述

业务同事反馈：[图片]请问，类似这种订单量超申购量的如何处理呢？

## 影响范围

- **影响系统:** 简道云 PM 系统
- **受影响用户:** 入库、对账相关岗位
- **影响数据:** 影响人工下单时订单量超申购量的判断。

## 原因分析

- 流程规则不清：申购剩余=申购-已下单；已下单为申购单+物料编码对应的订单数量之和；本次订单数量不能超申购剩余量；最终订单数等于手工输入的订单数量(输入)。

## 解决方案

1. 申购剩余=申购-已下单
2. 已下单为申购单+物料编码对应的订单数量之和
3. 本次订单数量不能超申购剩余量
4. 最终订单数等于手工输入的订单数量(输入)。 经讨论明确最终订单数等于订单对应物料的“最终订单数”，其值来自手工输入的“订单数量(输入)”

## 预防措施

- 这类是人做的订单而非预入库单订单，早期最终订单数可手填、且前期未做无订单入库数量限制，容易产生超量数据。
- 在流程说明中明确相关规则，避免重复咨询。
